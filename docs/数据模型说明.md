# 数据模型说明

## 星星与心愿扩展

IndexedDB v3 新增 `wishes` 表，索引 `id, childId, status`；服务端通用实体表同步支持 `wishes`。
Wish 包含 `id`、`childId`、`name`（1–80 字）、`picture`（内置插画标识）、`cost`（待确认时为 null，确认后为正整数）、`status`、`createdAt`、`updatedAt` 和通用同步/软删除字段。
状态顺序：`proposed` → 家长确认 `approved` → 孩子申请 `requested` → 家长送出 `redeemed`；申请可取消回 `approved`。

积分不另存可漂移的流水，以有效 TaskRecord / RoutineCheck 为事实来源：完成任务按 `日期 + 模板 ID（无模板则名称）` 去重，完成规则按 `日期 + 规则 ID` 去重，每项 5 星。
累计星数 = 有效完成项数 × 5；可用星数 = max(0, 累计 − 已兑现 − 申请中预留)。删除记录重算，漏做不扣星。
图标门槛为累计 5 / 25 / 60 / 120 星，不由兑换余额决定。没有额外医疗、冲突或情绪积分。
本地事务串行验证申请和兑现，服务端写入心愿前重新计算权威余额，防止多设备超额兑换；已兑现心愿不能被旧设备回退。
新表进入 JSON/CSV 导出、恢复校验、同步队列、远端增量、统计和清空链路，旧版备份缺少此表时按空表处理。

数据分两份，线上那份是主数据：

| 位置 | 介质 | 作用 |
| --- | --- | --- |
| 线上数据表 | 服务端 SQLite（`server/db.mjs`，默认 `data/sync.db`） | 主数据。换设备、换浏览器都读它 |
| 本地镜像 | 浏览器 IndexedDB，数据库名 `xiaobu-growth`（`src/db/db.ts`） | 离线可用 + 待推送队列 |

访问层：Dexie 4；所有读写都走 `src/db/repo.ts`，写入前必须通过 `src/lib/validate.ts` 的校验。
同步由 `src/db/sync.ts` 负责，本地写入和线上合并是两个不同的入口。

## 一、通用约定

| 项目 | 约定 |
| --- | --- |
| 主键 | `id`，UUID 字符串（`crypto.randomUUID()`，不可用时降级为时间戳 + 随机数） |
| 时间戳 | `createdAt`、`updatedAt`，ISO 8601 字符串（`new Date().toISOString()`） |
| 日期 | `date` / `weekStart` / `startDate` 等使用**本地自然日** `YYYY-MM-DD`，绝不使用 `toISOString().slice(0,10)` |
| 时刻 | `sleepTime` / `wakeTime` 使用本地 `HH:mm` |
| 枚举 | 统一存英文常量，界面文案集中在 `src/db/types.ts` 的 `LABELS` 里 |
| 空值 | 未填写用 `null`（不是空字符串），保证导出与统计一致 |
| 归属 | 除 `childProfiles`、`settings` 外的实体都带 `childId`，为以后支持多个孩子留位置 |
| 软删除 | `deleted?: boolean`，删除只打标记不删行，列表查询一律过滤掉它 |
| 同步序号 | `syncSeq?: number`，由服务端分配；本地刚写入、还没同步时为空 |

只有以下几个字段在 `updatedAt` 之外还保留 `createdAt` 之外的语义差异：无。所有实体都同时维护
`createdAt`（首次写入）与 `updatedAt`（每次更新），重复保存同一天/同一周的数据时只更新 `updatedAt`。

## 一之二、同步相关的两张本地表

这两张表只在本地存在，不参与导出，也不会上传给服务端。

### syncQueue（待推送队列）

`++seq, entity, &[entity+recordId]`。每条记录是
`{ seq, entity, recordId, payload, enqueuedAt }`。

- `repo` 内部的 `write()` 写完本地镜像后会调用同步引擎的 `writeHook`，把这条记录放进来。
- 唯一索引 `[entity+recordId]` 保证同一条记录只留最新一份，连续改十次也只推一次。
- 只有服务端确认写入成功之后才会从这里删除，所以断网期间录入的内容不会丢。

### syncState（同步元数据）

`key`（主键）+ `value`。当前键：

| key | 值 |
| --- | --- |
| `sync.seq` | number，本地已拉到的水位线，拉取时作为 `since` |
| `sync.resetSeq` | number，服务端「清空计数」的基线；首次连接只记基线，不触发本地清空 |
| `sync.lastSyncAt` | ISO 时间戳，最近一次同步成功的时间 |
| `sync.lastError` | string，最近一次失败原因，成功后清空 |
| `sync.endpoint` | string，接口地址，默认 `/api` |

### 服务端的 records 表

11 张实体表在服务端统一落成一张
`records(entity, id, payload, updated_at, sync_seq, deleted)`：
`entity + id` 做主键，`payload` 存这条记录的全部业务字段。
这样新增实体不用改表结构，同时保留同步需要的三件事：业务时间、全局递增序号、删除墓碑。
`meta` 表存全局水位线与 `reset_seq`。

## 二、表结构

### 1. childProfiles（儿童档案）

`id, name, isPrimary`

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `name` | string | 名字或称呼，必填，≤20 字 |
| `nickname` | string \| null | 小名，界面优先显示 |
| `focusWishId` | ID \| null（可选） | 孩子选择优先攒的心愿，随档案同步；已删除或已兑现时自动展示其他有效心愿 |
| `birthDate` | DayKey \| null | 出生日期 |
| `gradeLabel` | string \| null | 年级，如「二年级」 |
| `avatarEmoji` | string \| null | 预留（当前界面未使用） |
| `isPrimary` | boolean | 第一个创建的档案自动为主要档案 |
| `note` | string \| null | 备注 |

第一版界面只维护一个主要档案；创建档案时会自动写入 5 条内置家庭规则。

### 2. dailyLogs（睡眠与身体记录）

索引：`id, childId, date, &[childId+date]`（**唯一**：一个孩子一天只有一条）

| 字段 | 取值 |
| --- | --- |
| `date` | 记录日，以「起床那一天」为归属日 |
| `sleepTime` / `wakeTime` | `HH:mm`，可只填一个 |
| `nightCongestion` | `none` / `mild` / `moderate` / `severe` |
| `nightCough` | `none` / `once` / `several` / `frequent` |
| `snoring` | `no` / `sometimes` / `often`（可选） |
| `nightWaking` | `none` / `once` / `twice` / `three_plus` |
| `morningState` | `refreshed` / `ok` / `tired` / `very_tired` |
| `daytimeSleepiness` | `none` / `slight` / `obvious` / `severe` |
| `note` | string \| null，≤500 字 |

校验：日期合法；时刻若填写必须是 `HH:mm`；至少填写一项内容，避免产生空记录。
保存走 `saveDailyLog()`，同一天再次保存是**更新**而不是新增。
夜间时长由 `sleepDurationMinutes()` 计算：入睡晚于起床时按跨午夜处理（`22:00 → 06:30 = 510 分钟`）。

### 3. taskTemplates（学习任务模板）

`id, childId, name, archived`

`name`（≤40）、`subject`（≤20）、`defaultDifficulty`、`defaultMinutes`（1–180，可空）、
`steps`（最多 10 条，每条 ≤60 字）、`archived`（归档后不出现在可选列表，可恢复）。

### 4. taskRecords（学习任务记录）

`id, childId, date, templateId, status`

| 字段 | 取值 |
| --- | --- |
| `templateId` | 来源模板 ID，自定义任务为 `null` |
| `difficulty` | `easy` / `medium` / `hard` |
| `plannedMinutes` | 本次短时学习区间，1–180 |
| `startMode` | `independent` / `one_reminder` / `multi_reminder`，可空 |
| `completion` | `independent` / `partial` / `not_done`，可空 |
| `barriers` | `cannot_do` / `hard_to_start` / `distracted` / `tired` / `emotion` / `other` 的子集 |
| `actualMinutes` | 0–600，可空 |
| `parentNote` | ≤1000 字，可空 |
| `status` | `planned` / `running` / `paused` / `finished` |
| `timer` | `{ phase: 'focus' \| 'break', accumulatedMs, runningSince \| null }`，暂停时为 `null` 起点 |
| `childFeeling` | 儿童视图里孩子自选的感受（还行 / 有点难 / 很好玩 / 很累 / 不想做） |

计时逻辑：`已计时 = accumulatedMs + (runningSince ? now - runningSince : 0)`；
「结束并记录」把累计时长换算成 `actualMinutes`，并把 `timer` 置空。

### 5. routineRules（家庭规则）

`id, childId, trigger, active, order`

`builtinKey` 标记内置规则（`clothes_away`、`trash_bin`、`meal_safe`、`bedtime_prep`、`screen_deal`），
自定义规则为 `null`。`trigger` 取值 `morning` / `mealtime` / `bedtime` / `screen` / `anytime` / `custom`，
选择 `custom` 时 `customTrigger` 必填。`steps` 是给孩子看的视觉清单。`active` 为 `false` 表示暂停，
暂停后不出现在今日记录里，历史记录保留。

### 6. routineChecks（规则执行记录）

索引：`id, childId, ruleId, date, &[ruleId+date]`（**唯一**：同一规则同一天一条）

`status`：`done` / `partial` / `not_done` / `not_applicable`；`parentNote` 记录卡在哪一步。
未完成**不会**产生扣分、警告或连续打卡中断提示，只保存事实。

### 7. conflictLogs（家庭冲突复盘）

`id, childId, occurredAt, trigger`

`occurredAt`：ISO 时间戳（界面用 `datetime-local` 输入，按本地时间解析）。
`trigger`：`toy` / `attention` / `rule_inconsistency` / `screen` / `study` / `other`（选 `other` 时必填 `triggerOther`）。
必填文本：`childDescription`、`parentResponse`、`resolution`、`nextIdea`（各 ≤1000 字）；
`otherDescription` 可选。三个家长自省字段：`parentNagging`、`parentComparison`（true/false/null）、
`repaired`（`yes` / `partly` / `no` / null）。模型里没有任何「谁对谁错」的判定字段。

### 8. strengthMoments（优势与成长事例）

`id, childId, date, category`

`category`：`sport` / `create` / `care` / `organize` / `solve` / `other`。
必填 `event`（具体事件）、`childAction`（孩子做了什么）、`outcome`（结果如何），
可选 `childFeeling`。校验刻意要求事件、行为、结果分开填写，避免用「真棒」这类抽象标签代替行为证据。

### 9. weeklyReviews（每周复盘）

索引：`id, childId, weekStart, &[childId+weekStart]`（**唯一**：一个孩子一周一条）

`weekStart` 必须是**周一**（校验会检查 `getDay() === 1`）。
五个可空文本字段对应家长复盘表：`improvements`、`difficulties`、`effectiveSupport`、
`conflictSources`、`nextAdjustments`（各 ≤2000 字）。这几个字段只由家长手写，
系统不会自动填充结论。

### 10. experiments（家庭改进实验）

`id, childId, startDate, endDate`

必填 `problem`、`hypothesis`、`adjustment`、`startDate`、`endDate`、`metrics`（≥1 项）。
`endDate` 不能早于 `startDate`，周期建议 ≤120 天。
`result`：`improved` / `no_change` / `insufficient` / null（「证据不足」是一等公民，不是失败态）。
页面会按 `startDate–endDate` 自动带出观察期内的计数（`buildPeriodCounts`），只给数字，不给因果结论。

### 11. settings（设置）

`key`（主键）+ `value`（JSON 字符串）。当前键：

| key | 值 |
| --- | --- |
| `ui.childView` | boolean，是否处于儿童视图 |
| `security.parentPin` | `{ enabled, salt, hash }`，4 位数字密码的加盐哈希（仅为防误触，非加密） |
| `data.lastBackupAt` | ISO 时间戳，上次导出备份时间 |
| `data.lastImportAt` | ISO 时间戳，上次恢复时间 |

## 三、唯一约束与去重

| 表 | 唯一键 | 再次写入的行为 |
| --- | --- | --- |
| dailyLogs | `childId + date` | 更新同一条记录 |
| routineChecks | `ruleId + date` | 更新同一条记录（`parentNote` 不清空） |
| weeklyReviews | `childId + weekStart` | 更新同一条记录 |
| 其他表 | `id` | 主键相同即覆盖 |

导入备份时同样按「ID + 自然唯一键」跳过重复记录（`src/lib/transfer.ts` 的 `NATURAL_KEYS`）。

## 四、导出与导入

JSON 备份结构：

```json
{
  "app": "xiaobu-growth",
  "version": 1,
  "exportedAt": "2026-10-16T10:00:00.000Z",
  "counts": { "dailyLogs": 6, "...": 0 },
  "data": { "childProfiles": [], "dailyLogs": [], "...": [], "settings": [] }
}
```

- `app` 不匹配 → 拒绝；`version` 大于当前版本 → 拒绝并提示先升级应用。
- 导入模式：`merge`（默认，跳过重复）或 `replace`（先清空再导入）。
- 每条记录导入前都会过一遍对应实体的校验函数，不通过的记录计入 `skippedInvalid` 并在界面上列出原因。
- CSV 导出按表进行，编码 UTF-8 且带 BOM；多选字段用 `；` 连接，枚举导出为中文标签；
  含逗号、引号或换行的单元格按 RFC 4180 转义。

## 五、日期与时区处理

- 所有「哪一天」的判断都基于本地时区，`toDayKey(date)` 用 `getFullYear/getMonth/getDate`，
  不使用 UTC 方法，避免晚上 8 点后记录跑到第二天。
- 睡眠记录默认归属日：早上 6:00 前填写算前一天（`defaultLogDate`）。
- 一周从周一开始，`startOfWeek` 把周日归到上一周。
- 平均入睡时间在「夜间时间轴」上计算（`averageClock`）：中午 12 点前的时刻按 +24h 处理，
  这样 `23:30` 与 `00:30` 的平均是 `00:00` 而不是 `12:00`。
