# 小步成长（xiaobu-growth）

面向 7–9 岁儿童及其家长的家庭成长管理系统 MVP。它记录睡眠与身体情况、
学习任务的启动与完成过程、生活规则执行、家庭冲突复盘、优势事例和每周复盘。

数据存在**你自己部署的在线数据表**里（自带一个 Node + SQLite 服务），
所以换设备、换浏览器打开看到的是同一份数据；这台设备同时保留一份本地镜像，
断网时照常录入，联网后自动补传。健康信息和冲突记录只进你自己的数据表，
不经过任何第三方服务。

它不是 ADHD 诊断工具。儿童端提供图卡、星星和心愿礼物，用于庆祝具体行动；漏做不扣星，没有排名或连续打卡惩罚。
核心目标是让家长看清困难发生在哪里、哪种支持方式有效，帮助孩子逐步建立自主能力。

## GitHub Pages 与家庭云端同步

页面可发布到 GitHub Pages，路由使用 HashRouter，资源使用相对路径，适配仓库子目录。
自动发布配置见 `.github/workflows/pages.yml`。仓库只包含程序、测试和静态音频；`data/`、本地备份、环境变量和家庭连接码不提交。

GitHub Pages 不运行 Node 数据服务。独立云端服务使用 Supabase Edge Function 与 Postgres；所有手机和电脑共用一个家庭连接码，没有多用户系统。

当前线上入口：<https://weilai-zte.github.io/xiaobu-growth/#/child>。家庭项目 `xiaobu-growth` 部署在新加坡区域，创建时月费报价为 0 美元。
本机连接码保存在 `data/家庭连接码.txt`，已排除在 Git 及 JSON 备份之外。原 SQLite 迁移前备份为 `data/迁移前备份-20261019.sqlite`。
所有设备请使用上述线上入口；原 `localhost:8788` 数据库作为迁移前保留副本，不会自动接收云端后续更新。

真实云端检查（会创建并删除一条临时优势记录，不修改家庭已有记录）：

```bash
XB_CLOUD_VERIFY=1 npx vitest run tests/cloud.test.ts
node scripts/verify-cloud.mjs
```

未携带家庭连接码的读取必须返回 401。`tests/cloud.test.ts` 默认跳过；只有家长明确验证时才连接真实家庭库，GitHub CI 不持有连接码。

云端部署步骤：

1. 在获授权的 Supabase 项目应用 `supabase/migrations/20261019_family_sync.sql`。数据表在私有 schema，启用 RLS，匿名角色不可直接读取或写入；RPC 仅 `service_role` 可调用。
2. 为家庭生成至少 24 字符的随机连接码；只将其 SHA-256 哈希替换到 `supabase/functions/xiaobu-sync/index.ts` 占位符后部署。Edge Function 自行验证家庭连接码，因此网关 `verify_jwt=false`；不向前端提供服务密钥。
3. 将 GitHub 仓库变量 `VITE_SYNC_ENDPOINT` 设置为 `https://项目引用.supabase.co/functions/v1/xiaobu-sync`。它是公开接口地址，不是密钥。
4. 将现有 SQLite 的各实体记录通过受保护的 `/sync` 导入云端，核对记录数；原 SQLite 数据库继续保留。不要把数据库或导出 JSON 提交到 GitHub。
5. 每台设备首次打开网页输入同一个家庭连接码。码保存在这台浏览器设置中，不进入 JSON 备份。之后的写入进入离线队列，联网后同步，页面恢复前台也会重试。

云端数据库未部署或尚未填写接口时，GitHub 页面显示明确的待连接说明，不误导用户重新建一个孤立档案。
家庭连接码相当于访问所有家庭数据的钥匙，请由家长保存；不要放在网页源码、公开链接或仓库中。现有本机家长门锁仍只防儿童误触，不是云端身份验证。

### 打卡声音

儿童任务和生活图卡成功保存后播放“你太棒了！又完成了一小步。”，并显示同样的文字。
音频随页面加载，不向语音服务发送孩子的信息。可以关闭或试听；iOS 使用点击内静音解锁，保存成功后再播放，保存失败不播放。

## 一、快速开始

环境要求：Node.js 22.5 以上。数据服务用的是 Node 内置的 `node:sqlite`，
不需要额外装数据库，macOS / Windows / Linux 都行（开发机上用的是 v22.22.3）。

```bash
cd /Users/weilai/Documents/ChatGPT/习惯养成
npm install --registry=https://registry.npmjs.org/
npm run build            # 先构建一次页面
npm start                # 启动：托管页面 + 提供数据接口，http://localhost:8788
```

启动日志里会打印本机局域网地址（形如 `http://192.168.1.20:8788/`），
手机连同一个 Wi-Fi 就能直接打开，**不需要公网，也不需要 HTTPS**。

> 服务是前台进程，**关掉终端（或按 Ctrl+C）它就停了，页面会显示打不开**，重新执行 `npm start` 即可。
> 也不要直接双击 `dist/index.html`：浏览器在 `file://` 下会拦住 ES module，只会得到一片空白。

改前端代码时用开发模式：前端跑在 5174，通过代理把 `/api` 转到 8788。

```bash
npm start                # 终端一：数据服务
npm run dev:ui           # 终端二：前端开发服务器，自动打开 http://localhost:5174
```

测试与完整校验：

```bash
npm test                       # Vitest：数据、界面、同步与积分用例
npm run typecheck              # TypeScript 严格模式
npm run verify                 # typecheck + test + build 一次跑完
node scripts/verify-sync.mjs   # 换浏览器端到端验证，需要先 npm run build
```

## 二、在 iPhone 上使用

儿童端入口是 `/#/child`，生活图卡是 `/#/child/rules`，心愿小屋是 `/#/child/progress`。
完成图卡即记录完成，不再要求孩子填写障碍、备注和多项选择。复杂记录仍由家长在原页面填写。

### 星星与心愿（试用规则）

- 每项学习任务或生活规则完成得 5 颗星。同一任务（模板或名称）、同一规则当天只算一次，历史有效记录及补记也计入；不按速度或正确率加分。
- 星星根据有效完成记录与已保存的冒险奖励计算；撤回或删除完成记录会撤回对应任务星星。没有连续天数加成；每日冒险规则见文末。
- 累计获得 5 / 25 / 60 / 120 颗星，点亮小芽 / 小花 / 小树 / 火箭。兑换只影响可用余额，不影响累计计数；删除历史记录可能影响图标状态。
- 孩子选插画、填写自己的礼物或活动心愿。家长从「更多 → 星星与心愿礼物」确认正整数兑换星数。
- 申请兑换时预留星星；可以取消并释放。家长实际送出后点击「确认已送出礼物」，成为历史记录，不会重复兑换。
- 心愿与状态进入服务端 SQLite 同步、JSON 备份和 CSV 导出。服务器对申请和兑现再次检查余额；多设备离线冲突时提示同步失败，可取消申请后重试。未成功同步前不要据此实际送出礼物。

图卡使用随页面一起加载的内联 SVG 插画，无外部图片请求。手机采用两列大图卡，并支持键盘焦点和减少动态效果设置。

当前限制：心愿暂不支持照片上传；家长确认沿用已有本机家长门锁，不是线上账号权限。服务仍需在电脑上运行；没有部署到公网，离开同一网络无法通过局域网地址访问。

最简单的方式就是直接开 `npm start`，用手机访问启动日志里那个局域网地址
（`http://192.168.x.x:8788/`）。数据本来就存在你自己电脑上的数据表里，
所以手机端只是显示层，换手机、清了浏览器数据都不会丢记录。

### 方式 A：家里局域网直接用（推荐）

```bash
npm run build && npm start
ipconfig getifaddr en0     # 也可以直接用启动日志里打印的地址
```

iPhone 连同一个 Wi-Fi，Safari 打开 `http://192.168.1.20:8788/`，然后
「分享」→「添加到主屏幕」。这样用起来和原生 App 一样是全屏的。

HTTP 下 iOS 不会给网页做长期离线缓存，但**数据不会丢**：断网时改动先存在手机上，
恢复连接会自动补传。要长期离线可用，再走下面的方式 B。

### 方式 B：放到一台常开的机器上 + HTTPS

页面和数据服务可以部署到任何能跑 Node 的地方（家里的树莓派、NAS、云主机都行）。
放进 HTTPS 之后，Safari 才会给完整的 PWA 离线能力：

```bash
cd /Users/weilai/Documents/ChatGPT/习惯养成
npm run build
PORT=8788 node server/index.mjs     # 前面挂一个 Nginx / Caddy 做 HTTPS 反向代理
```

拿到 https 地址后，在 iPhone 上用 **Safari** 打开：

1. 点底部「分享」按钮 → 「添加到主屏幕」→ 命名「小步成长」。
2. 从主屏幕图标打开（不是从 Safari 标签页打开），这时它已经是独立的全屏应用。

> 放到公网之前请先想清楚权限问题：当前版本**没有账号体系和鉴权**，
> 谁能打开这个地址谁就能看到全部记录。公网部署至少要加一层 Nginx 的 Basic Auth，
> 或者只在内网 / VPN 里暴露端口。

## 四、数据模型

数据有两份，**线上那份是主数据**：

- **线上数据表**：服务端 SQLite（默认 `data/sync.db`），11 张实体表统一落在一张
  `records(entity, id, payload, updated_at, sync_seq, deleted)` 里。
  这样新增实体不用改表结构，同时保留同步需要的三件事：业务时间、
  全局递增序号、删除墓碑。
- **本地镜像**：浏览器 IndexedDB（数据库名 `xiaobu-growth`，通过 Dexie 访问），
  保证断网也能用。11 张实体表加 2 张同步用的表 `syncQueue`（待推送队列）和
  `syncState`（水位线等元数据）。

`childProfiles`、`dailyLogs`、`taskTemplates`、`taskRecords`、`routineRules`、
`routineChecks`、`conflictLogs`、`strengthMoments`、`weeklyReviews`、`experiments`、`settings`。

字段、索引、唯一约束与校验规则的完整说明见 [docs/数据模型说明.md](docs/数据模型说明.md)。

约定：

- 每条记录都有 `id`（UUID）、`createdAt`、`updatedAt`。
- 删除是**软删除**：记录本身留着，只打上 `deleted` 标记，列表查询会过滤掉。
  只有这样「删除」这件事才能同步到别的设备，也不会被别的设备重新拉回来。
- 日期统一用**本地自然日**字符串 `YYYY-MM-DD`（不用 `toISOString`，避免时区跨日错乱）；
  时刻用 `HH:mm`；时间戳用 ISO 8601。
- 睡眠记录以「起床那一天」为归属日，早上 6 点前填写的默认算前一天。
- 同一天同一孩子只有一条睡眠记录；同一规则同一天只有一条执行记录；每周一条复盘记录。
  再次保存是更新，不会产生重复。

## 五、在线同步

页面上的每次改动都是「先写本地镜像并进待推送队列，再推给线上数据表」，
所以断网时录入不会失败，也不会丢。

**怎么判断两边一致：** 设置页 →「在线同步」卡片会显示当前状态、最近一次同步时间、
待同步条数，以及这台设备和线上各自的水位线（`syncSeq`）。两个数字一致就说明对齐了。

**冲突怎么处理：** 两边改了同一条记录时，按 `updatedAt` 后写覆盖。设备时间戳更旧的那次
写入会被服务端拒绝，并把线上版本回传给客户端对齐，不会出现静默覆盖。

**清空是怎么传播的：** 服务端维护一个只增不减的 `resetSeq`。别的设备点「清空全部数据」后
这个值会变大，其他设备下次同步时发现它变了，就把本地镜像一并清掉再从零重拉。
首次连接的设备只会把这个值记成基线，**不会**因为历史清空记录而误删本地数据。

**接口**

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET | `/api/health` | 服务状态、各表条数、当前水位线 |
| GET | `/api/sync?since=<seq>` | 拉取大于该序号的所有变更（含删除墓碑） |
| POST | `/api/sync` | 提交 `{ since, changes }`，返回合并后的增量 |
| POST | `/api/clear-all` | 清空全部记录并推进 `resetSeq` |
| — | `/api/<实体名>` | 常规 CRUD（`GET` / `POST` / `PATCH` / `DELETE`） |

页面和数据服务在同一处时，前端直接用相对路径 `/api`；分开部署时在设置页里填完整地址即可。

## 六、备份与恢复

**导出**

- 设置页 →「导出全部数据（JSON）」：一个完整备份文件，包含所有表与设置。
- 设置页 →「导出哪张表（CSV）」：按表导出 CSV，UTF-8 带 BOM，Excel / Numbers 打开中文不乱码。
- 导出后「上次导出时间」会被记下来；「更多」页超过 7 天没备份会提醒。

**恢复**

1. 设置页 →「从备份恢复」→ 选择 `.json` 文件。
2. 弹窗里选择恢复方式：
   - **合并**（推荐）：保留现有数据，按 ID 和自然唯一键跳过重复记录。
   - **覆盖**：先清空现有数据再导入。
3. 导入完成后给出统计：新增多少条、跳过重复多少条、跳过无效多少条（并说明原因）。

导入时会逐条走校验，格式不对的记录会被跳过并报告，不会污染现有数据；
不是本应用导出的文件、或版本比当前应用新的文件会被直接拒绝。

**删除**

- 各页面都能删除单条记录，删除前会弹确认框。
- 设置页可以按表浏览记录并删除单条。
- 「清空全部数据」需要先导出备份，并在确认框里手动输入「清空」两个字才会执行，不可撤销。
  它会**先清线上、成功后再清本地**：线上没清掉就整体放弃，免得本地空了又被云端数据拉回来。

## 七、隐私

- 记录只进**你自己部署**的数据表，不经过任何第三方服务。应用没有接入广告、
  统计 SDK，也没有第三方 AI 服务，没有账号体系。
- 家长密码（4 位数字）只做本地校验，用于挡住儿童视图下的敏感页面，**不具备加密作用**，
  请把它理解成一道防误触的门。健康信息与冲突记录默认不展示给孩子和其他家庭成员。
- 数据服务本身没有鉴权：**能访问到 `:8788` 的人就能看到全部记录**。
  内网自用没问题，放到公网前请先加一层反向代理的登录验证。
- 换设备、换浏览器不再会丢记录（数据在线上），仍建议定期导出 JSON 留一份离线备份。

## 七、技术栈与目录

- Vite 5 + React 18 + TypeScript（严格模式）
- Dexie 4（IndexedDB），`useLiveQuery` 做响应式数据流
- React Router 6（HashRouter，静态托管下刷新不会 404）
- 服务端：Node 内置 `node:http` + `node:sqlite`，零运行时依赖
- 手写 CSS（`src/styles.css`，含浅色/深色主题、三档响应式与打印样式），不引入 UI 框架
- 图表全部手写内联 SVG（`src/components/charts.tsx`），不引入图表库；图标同样是内联 SVG，不用 emoji
- Vitest + Testing Library + fake-indexeddb 做测试
- 手写 Service Worker（`public/sw.js`）实现离线缓存，没有用 workbox

```
src/
  db/         types.ts（实体与中文选项）、db.ts（Dexie schema）、repo.ts（带校验的读写）、
              sync.ts（同步引擎：拉增量、推队列、判冲突、处理整体清空）
```

## 九、当前已知限制

1. **单家庭单实例**：只有一个家庭、一个主要儿童档案，没有账号体系与多租户，
   多人共用时只能靠「家长模式 / 儿童视图」这个开关区分。
2. **数据服务没有鉴权**：接口是开放的，能访问到端口的人就能读写全部记录。
   内网自用没问题，放到公网前必须自己加一层登录验证。
3. **数据服务是前台进程**：`npm start` 关掉终端就停。要常开需要自己配 launchd / systemd。
4. **家长密码是防误触，不是安全边界**：密码只做本地校验，数据本身没有加密，
   能打开浏览器配置文件或直接访问数据接口的人可以看到数据。
5. **没有自动备份**：数据虽然在线，仍建议手动导出 JSON；服务端数据库文件损坏时只能靠之前的导出。
6. **HTTP 访问没有完整离线能力**：iOS 上给 Service Worker 做长期缓存需要 HTTPS（见第二节）。
   但数据不会丢。断网时改动先存在本机队列里，联网后自动补传。
7. **儿童视图是简化版**：只有任务、生活清单和进步三页，没有单独的孩子账号和权限体系。
8. **就医摘要只有打印/存 PDF**：不支持直接分享到微信或生成图片（iOS 可用分享菜单里的「打印」→ 存为 PDF）。
9. **周汇总只做计数与平均值**：不判断因果、不评分，超过记录范围的分析需要家长自己看。
10. **图表只覆盖两个维度**：学习投入按学科、睡眠按入睡–起床时段。规则执行、冲突、
    优势事例目前还是文字与计数，没有做成图。
11. **未做自动化无障碍审计**：已按键盘可操作、标签关联、`aria-live` 提示、44px 点按目标设计，
    图表也都配了文字摘要与可展开数据表，但没有跑 axe 等工具，也没有真机读屏测试。
12. **任务计时精度依赖设备**：切到后台时按时间戳计算，误差通常在 1 秒内，
    但浏览器关闭后不会在后台继续计时。
13. **同步是「最后写入者胜出」**：两台设备几乎同时改同一条记录时，以较晚的时间戳为准，
    不提供逐字段合并或冲突人工裁决界面。
14. **不做的功能**（按需求明确排除）：ADHD 自动诊断或风险评分、自动健康与用药建议、
    自动判定孩子是否懒惰/拖延、兄弟比较排行榜、积分惩罚与连续打卡、自动生成因果结论的 AI 分析、
    第三方账号体系、复杂通知与第三方集成。

## 十、开发约定

### 儿童图卡体验（竞品调研后的增量改版）

- 首页的伙伴「小步」从蛋开始，按新增冒险经历成长，不需要喂养，漏做不会难过、扣星或清零。旧星星和礼物记录不变。
- 「我先做这个」只调整当前页面的任务顺序，不产生打卡；实际完成后点大图卡才记录并获得原有的 5 颗星。
- 孩子可以选择优先攒的心愿，首页显示真实余额和还差多少星；选择随档案跨设备同步。图片建议只预填名称，不会自动建立心愿或代替家长确认星数。
- 成长页最近 7 天的小脚印由真实完成记录生成；没有记录的日期保持中性空位，不做连续天数惩罚。
- 本轮借鉴了用户提供调研中的陪伴、自主选择、可见进步和家庭体验奖励，没有采用其中未经核实的市场数字，也没有加入排行榜、照片审核或复杂游戏经济。

### 小步的成长与每日冒险

- 当天完成任务获得满15星可出发一次，不消耗余额；兑换礼物不影响资格。奖励星不用于凑当天门槛。按北京时间划分每日，不补抽历史日期。
- 选择花草原、小溪边或小树林，云端保存一段故事；每次获得2、3或5星（各约三分之一）和一份叶子、树枝或石头（各约三分之一）。无空奖、付费抽取、大奖或重抽。
- 成长阶段由累计冒险次数决定：0蛋、1裂壳、2雏鸟、5练飞、9长大、14小窝、21小家；材料自动成为搭窝的故事进度，不是额外兑换货币。休息和兑换不会倒退。此后仍能冒险，第一版成长外观到小家为止。
- 冒险需要网络，普通打卡仍可离线。未收到结果时可重试同一路线；服务端按 `adventure:childId:日期` 幂等处理，手机电脑同一天只领奖一次。断开后重连可取回已保存结果。
- `adventureRuns` 进入JSON/CSV与恢复链路，但不能通过普通写接口新增、修改或单删；恢复只可同步云端已存在的奖励。云端奖记录本身遗失时不能用本地备份自行签发奖励，需受控修复。家庭整体清空仍会同时删除成长经历。
- 云端增量部署源在 `supabase/bird_adventure.sql`，包含更新的兑换校验与原子领取函数；先部署数据库函数，再部署同目录的同步Edge Function，最后发布页面。原有同步接口兼容旧页面。

- 新增字段要先改 `src/db/types.ts`，再在 `repo.ts` 的读写函数里同步，最后补 `validate.ts`。
- **所有写入都必须走 `repo` 内部的 `write()`**，它负责写本地镜像并触发入队。
  绕过它（直接 `db.xxx.put`）的记录不会进待推送队列，也就同步不出去。
  唯一的例外是同步引擎把线上数据合并回本地，那条路径是 `applyRemote()`。
- 列表查询一律用 `alive()` 过滤掉软删除墓碑，否则删掉的记录会重新出现在界面上。
- 任何写入都必须先过校验，仓库层会再校验一次，测试里覆盖了「无效记录写不进去」。
- 服务端新增实体时，只需把实体名加进 `server/db.mjs` 的 `ENTITIES`
  和 `src/db/db.ts` 的 `ENTITY_NAMES`，不用改表结构。
- 生成给孩子或家长看的文案，走 `src/lib/feedback.ts`，那里的 `FORBIDDEN_WORDS` 有测试守着，
  不要绕过它直接拼字符串。
- 汇总类文案走 `src/lib/insights.ts`，只允许写观察到的事实，不允许写「因为/所以」。
- 图表走 `src/components/charts.tsx`，每张图都要带一句话结论和可展开的数据表，
  颜色不能是唯一的区分手段。
